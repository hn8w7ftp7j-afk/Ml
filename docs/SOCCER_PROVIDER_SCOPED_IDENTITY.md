# Provider-scoped Reader identity

The earlier identity guard required an independently complete global schedule authority and therefore always returned false. The retained matching specification requires a unique original-quote match, source/event/team/kickoff bindings and conflict rejection; a universal completeness assertion is not necessary to establish a match inside the pages actually returned.

The existing server schedule adapter now registers a process-local immutable projection of its two UTC pages for one Taipei league/day. The projection retains all returned normalized candidate identities and the existing source URLs, hashes and fetch times. It does not acquire or archive any additional raw provider documents. Serializable caller coverage flags do not create this receipt, and mutation of the registered board invalidates it.

Analysis checks the selected stable event/team IDs, normalized neutral-site flag, exact source-page scope, summary source, current cutoff and original Reader aliases/time. Distinct event IDs with the same matched teams/time remain ambiguous. The saved derived receipt binds all actual direction keys, prices, original rows and provenance; the compact forward capture retains these bindings. A client-safe SHA-256 implementation verifies the derived receipt. Subsequent server consumers must first validate the immutable original analysis revision/database receipt; a recomputed hash on an arbitrary HTTP object is not authority.

The status is `PROVIDER_SCOPED_UNIQUE_MATCH`. It explicitly reports `providerCompletenessVerified=false`, `independentlyConfirmed=false` and `formalEligible=false`. This does not certify universal schedule completeness, source rights, independent corroboration, a bet's actual account terms, calibration, R uncertainty or formal scoring acceptance. Existing source/model/OOS/settlement/period/scoring gates continue to apply.

Legacy snapshots are not remapped or upgraded. A future source-bound observation can be used only with its own original saved receipt and time; the new evidence does not manufacture historical availability or promote a self-asserted legacy betting record.

The unmocked integration fixture enters the actual schedule fetch adapter, summary normalizer and Reader parser, then exercises immutable PostgreSQL fixture readback and the compact market-return collector. Synthetic network data and local database tests are not Production or independent predictive acceptance.
