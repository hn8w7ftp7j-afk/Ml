## 1. 核心方向與六層整合

**完整分析、低頻篩選、允許零場。** 不設定每日保底下注場數。沒有符合條件場次時，網站顯示零場與原因分布；不得用低門檻補足場數。

所有輸入與決策對齊同一分析截止時間 `t_eval`，各來源不必同時更新，但各自時間、新鮮度、缺漏與版本須可追溯。

### 1.1 因素與權重

不將任意「進攻 30%、防守 30%」當成最佳模型配方。每個因素須註明來源、資料可用性、目標、進入模型的位置、與其他因素的重疊，以及樣本外增益。以攻守強度為基礎，陣容與條件調整後產生比分分布，再按契約結算並檢查誤差。不能為了清單完整而任意加入加減分。

### 1.2 半場模型與跨期邊界

- 等長且固定進球強度的齊次 Poisson 假設下，`lambda_1H = 0.5 * lambda_FT` 可作簡化基準；這是強度參數的折算，並非勝率／比分機率折半。
- 生產參數須按目標聯賽之半場資料與補時口徑校準；不使用未核對的固定經驗百分比。
- 低比分、雙方關聯、時間差異、領先／落後反應、紅牌／十二碼及尾端須檢查，但不強制先採最複雜模擬。突發事件作情境或機率處理，不預先指定某隊必然遭遇。
- 跨期一致性保證層級須明示，詳見附錄 D；逐隊與總進球門檻單調性不是完整二維比分一致性的充分條件。

## 2. 資料時間、版本與可回放性

### 2.1 截止時間與雙時間維度

1. 只使用在 `t_eval` 前已取得、且當時分析流程確實可用的資訊。來源發布時間不能代替本系統取得證據。
2. 分清來源發布時間、系統取得／接收時間、持久化時間，以及必要時的分析可用時間；不要求每個系統新增所有欄位，但必須能證明截止前可用，不能混用語意。
3. 知悉時間與業務適用範圍分開。例如下輪聯賽停賽不能套用今晚 UCL；可適用的賽事、場次、期間與有效範圍須明確。
4. 時區、時間精度、來源排序與同時事件處理須在實作附錄定義。歷史查詢不依事後才確定的賽事／人員資訊修正原決策。

### 2.2 內容版本與核對事件

- `first_fetched_at` 綁定**該版具體內容**。`revision_id`、`content_hash` 作識別，不是時間欄位。
- 修改內容須新增版本及新取得時間；不得沿用實體原本的舊時間卻讀取後來修訂的傷停、先發或報價。
- 內容首次取得證據不可覆寫。核對內容未變動的事件採追加保存，並關聯內容版本。
- `last_verified_at` 只表示新鮮度，不能取代首次取得時間。歷史回放僅取 `verified_at <= t_eval` 的核對事件，杜絕讀到未來核對造成負資料年齡。
- 歷史版本、核對日誌與當前快取可併存；當前快取可更新，不能作為歷史回放唯一證據。不能僅以 `UPDATE`／`INSERT` 判定整個系統是否合格。
- 未保存的歷史取得證據標為 `UNKNOWN`。事後重建、回填、重新下載不能追認為原系統當時已知。若做重建研究，與原系統真實回放分開標示。

### 2.3 分析可重現性

每次分析須能關聯 `analysis_run_id`、`t_eval`、賽事／期間／市場身分、資料與來源版本、陣容快照、比分分布版本、模型／特徵／校準／契約／排序／QA 規則版本及報價版本。具體欄位可依既有架構映射，但不能缺少決策所依據的證據。

## 3. 八方向、契約與收益

### 3.1 八方向與機率範圍

需求標的是全場與上半場各四方向：主／客讓球、大／小球；須由前置核對確認既有實際標的、符號、期間與映射。獨贏、晉級、含加時等其他市場另列契約，不混入八方向。

比分分布及每一市場內**互斥且完備**的結算結果，各自非負且加總為一；八方向可能重疊，不要求跨市場合計為一。兩側正損益機率也不一定互補。各方向有無共用比分分布、半場／全場如何關聯須明示。

### 3.2 結算契約

- 每筆價格須有來源、時間、主客方向、正負號、球頭、水位格式、期間及契約版本。價格比較須同時間、同市場、同期間、同契約。
- 整數盤邊界走盤、四分之一盤拆注、按契約比例結算及其他機制分開核對；「來源有多種契約」不是單筆契約分類。
- 一般亞洲盤淨收益 `{b, b/2, 0, -0.5, -1}` 僅為適用契約示例；不能直接當成未核對台盤的正式派彩。
- 退水**計算基數／公式**與**適用條件／結算狀態**分開記錄。按本金計算與僅輸單適用可以同時成立。有效金額、上限、進位、時間及成本等按真實契約核對。
- 上半場為其常規時間含補時；全場為正規時間含補時、不含加時及點球，仍以實際市場契約為準。不能對所有市場寫死 90 分鐘。
- 腰斬、延賽、改期、裁定勝負、結果更正、爭議及比分缺失依各契約和期間處理；上半場可能有效而全場取消。無法核對的契約不得進入正式候選。

### 3.3 W、R 與市場參考機率

既有 `S >= 7.2`、`W > 0`、`R > 0` 為本次保留的候選條件，不因需求整理而重新最佳化或默默改變公式。足球適用之實際公式、單位、是否含退水與統計性質仍須核對。

若另定義分析用期望淨收益，可寫為「比分／情境機率乘該契約淨損益後求和」；該表示式**不能在未查驗程式前宣稱就是既有 W**。市場去水參考機率與實際報價的損益兩平條件不同。模型機率高於去水市場機率不自動表示正 EV；有走盤、比例、退水時須回到逐比分損益。

明星人氣與盤口移動若無投注流量或其他識別證據，不能直接作因果解釋。報價可取得性須有當時紀錄，不能用事後價格反推。

## 4. 低頻篩選、資格生命週期與狀態

### 4.1 六道流程

1. 資料、隊伍／球員身分、盤口或契約有錯：當次 run 的 QA 設 `BLOCKED`。
2. 關鍵先發／分鐘未知且合理情境會翻轉判斷：待確認。
3. 模型／聯盟／市場尚未完成適用驗證：研究／影子分析。
4. 通過既有 `S >= 7.2`、`W > 0`、`R > 0` 與 QA 才可具候選資格。未核對公式與契約前不得以推定數字取得正式資格；不另設任意六成勝率門檻。
5. 保存價格、陣容、資料與規則快照；關鍵變動後先使舊資格失效，重檢通過再恢復。須由 API／資料庫約束，不能僅撤下畫面標示。
6. 全八方向保存分析狀態與結果；同場主方向由事前固定規則選出，其餘保留比較，不當作多份獨立把握。無候選時不強行指定可下注主方向。

重疊原因、狀態優先序、合理情境定義、數值精度及門檻實作須寫入附錄；保留所有原因，不能賽後挑選對績效有利的分類。

### 4.2 報價重核與完整重算分離

- 每次實質報價變更都新增報價版本，按新價重核損益與候選條件。舊價格資格不能套用新價格，即使變動小於通知門檻。
- 若比分分布之依賴資料未變且仍適用，可按規則核對後重用。若報價本身是比分模型輸入，則依依賴關係觸發所需重算，不能假設可直接重用。
- 變動門檻只能控制通知或昂貴的完整模型重算頻率，不能免除新價格的資格檢查。
- 分別保存：新報價是否建立、舊資格是否失效、新價格重核狀態（待執行／處理中／完成／失敗）；「未完成重核」不等於「沿用舊資格」。未通過重核的新價不能發布有效候選。

### 4.3 同步失效與並行控制

當**本系統已取得、採納並識別**會影響資格的更新時，須同步使相關舊資格失效並更新目前資格版本；不宣稱尚未收到的外部變動已反映。

發布目前候選或授權新請求時，透過原子條件更新，或具適當隔離與約束的交易，核對目前資格版本、依賴資料、報價版本及有效期限。不得僅比較最近完成的分析，也不得非原子地「先查再寫」。新任務 B 計算期間，舊任務 A 即使稍後完成，也只能保存歷史結果，不得重新發布舊候選。具體代次、鎖定、條件更新或同等機制須於附錄 A/E 附證據。

過期資格不得作為「目前有效候選」返回或通過新的資格授權；歷史查閱、稽核、事件保存及已發生的實際接受結果（含延遲回報）仍如實留存，標示原資格／報價／契約版本、事件時間與回報時間。現在失效不追溯抹除過去真實事件。

## 5. 模型訓練、選擇、校準與獨立驗收

### 5.1 因果時間隔離

- 基礎訓練擬合攻守等係數；驗證選擇特徵、衰減、模型結構、組合及篩選政策。
- 擬合校準器或模型組合的資料，對該層就是訓練資料；不能再作獨立驗收。
- 可採四段時序隔離或正確的 rolling／nested／時間 cross-fitting。每個歷史預測點的資料、標籤、特徵選擇、超參數、模型、組合、校準與規則只能使用當時已可用的歷史資訊。
- 以比賽為單位處理關聯。相同比賽的方向、報價、run 或快照不可散入不當的訓練／測試分割。結果尚未確定、尚未取得或未可用的標籤不能訓練當時模型。
- 測試集保留且不參與選擇。看完結果再修改，該批對被調整程序已不是未使用驗收資料，須新的未使用資料。反覆比較驗證集仍有選擇偏誤，應記錄比較與選擇。
- 驗證集的顯著改善是開發政策，不能代替最終 OOS 證據；不因複雜度增加就預設準度提高。
- 模型／聯盟／市場之驗證資格與版本、樣本期間、標的及有效狀態明確綁定。尚未驗證維持研究；不能跨域冒用。

### 5.2 固定目標與恰當評分

| 任務 | 評分與限制 |
| --- | --- |
| 1X2 | 三分類 Brier、Log Loss；說明 Brier 正規化慣例。市場基準為同時間同規則的去水 1X2，去水方法須固定。 |
| 精確比分 | 基準為實際比分之負對數機率。二維比分不能任意攤平成一維 RPS；使用多維分數時先定義公式、距離與權重。處理截斷尾端與觀測比分落於網格外的規則，不可默默丟棄。 |
| 契約結算分布 | 依該契約的互斥完備結果採多類 Brier／Log Loss；類別有適當順序時可用 RPS。不能強行把所有比例盤壓為固定五態。 |
| 二元正損益事件 | 明確定義正損益、退水／費用及 Push/Void 的處理；以該二元事件評分，不能與全贏率混稱。 |
| 平均淨收益 | 可評估預測均值與實現收益的 MSE、平均偏差及分群偏差；不能取代完整結算分布評分。 |

半贏／走盤不得未定義目標就填 `0.5` 當二元事件。明確定義分數型收益變數後，平方損失可評估其均值，但不能解讀為原事件機率。平均誤差為零可能是不同群體高低估抵銷。

僅憑 1X2 報價無法唯一還原完整比分分布；不得把 1X2 當無假設比分基準。模型與市場比較必須同一事件空間。

### 5.3 校準、Brier 分解與小樣本

Brier／Log Loss 降低不單獨證明校準變好；Brier 的 reliability、resolution、uncertainty 含義不同。保留校準曲線與分群檢查，不只看漂亮程度。

常見二元分箱定義分欄記錄：

```text
ECE = sum_b w_b * abs(mean(p)_b - mean(y)_b)
REL = sum_b w_b * (mean(p)_b - mean(y)_b)^2
```

注明範數、分箱方式、各箱樣本量、預測分布、估計限制與區間；分箱 REL 是指定分箱下的估計，不可不加條件當作所有連續預測的精確分解。

固定預測與分箱時：

```text
E[(p_bar_b - Y_bar_b)^2]
  = (p_bar_b - q_bar_b)^2 + Var(Y_bar_b)
```

其中 `q_i` 為真實事件機率，不能以模型 `p_i` 代替。在箱內獨立同質 Bernoulli 的假設下，對 `n_b >= 1` 有 `Var(Y_bar_b) = q_b*(1-q_b)/n_b`。對 `n_b > 1`，`y_bar_b*(1-y_bar_b)/(n_b-1)` 才是此變異的無偏估計項。這些為上述假設下的性質，不宣稱是唯一可能成立的條件。

- 異質機率與同場／跨場相關須處理實際變異與共變異。
- 去偏估計可能為負；截零後不能仍稱無偏。去偏可能增加變異。
- 篩選改變樣本量、預測分布、分箱與相關性；不能說 500 場變 40 場，噪聲必然按固定倍數放大。
- Kernel／cumulative 校準方法各有假設，不能只因不分箱就宣稱無偏或可無條件公平比較。
- 全樣本校準不保證入選子集校準。主方向選擇可能放大估計誤差，但不必然造成高估。須回放完整選擇程序，分別評估入選子集及與市場分歧分層。
- `mean(p_selected) - mean(y_selected)` 只測平均校準偏差，不能代替完整條件校準。

### 5.4 區間與累積收益檢定

1. 未來實際收益的預測區間可用後續實現結果檢查涵蓋率，須注明目標與保證範圍。
2. 真實勝率／期望收益的信賴區間針對不可逐場觀測的均值；須交代理論、假設、構造及適當模擬，不能用單次實現收益是否落入區間計算均值 CI 的逐場涵蓋率。
3. 一般逐場單側下限的程序保證 `P(L_i <= mu_i) >= 1-alpha` 不自動保證每個已實現情境 `mu_i >= L_i`，也不保證全部下限同時成立。因此不能僅憑逐場 CI 就認定 `Y_i-L_i` 累積為所需次鞅。
4. 累積實現收益可測預先定義的群體收益或條件均值主張，但須另定虛無假設，處理下限失敗機率、適應性入選、同時比賽資訊順序及反覆查看／停止規則；允許隨時停止時須有相應時間一致保證。
5. 拒絕檢定表示資料與聯合假設不相容，不等於每個下限都錯；未拒絕不代表已證明有效。
6. R、陣容情境敏感範圍、模型抽樣／校準誤差及收益區間分欄，不互相冒充。

## 6. 低頻策略與報表驗收

### 6.1 比較與分母

在事前定義的相同母體、時點與可比市場下比較不同入選比例的勝率、機率損失、校準、收益及樣本量。低頻是否更準、是否正收益，分開驗證；不能當成前提。所有未選中、失敗、缺資料及跳過項目留存，避免生存者偏誤。

須逐項公布：原始賽事母體、可評估場數、失敗／不足／無盤數、入選場數、入選比例、市場覆蓋率、去重比賽數、實際接受數、已結算數、收益及不確定範圍。去重比賽數不等於證明各比賽統計獨立。

各指標分母由附錄 C 固定：機率評分、候選覆蓋、已接受紀錄、ROI／單位收益不能共用含糊分母。若本金不同，說明加權與總額計算；未結算、無法結算不硬填零收益。

### 6.2 結算結果完整分類

報表至少區分：

1. 全贏。
2. 半贏。
3. 其他比例的部分贏，保存確切比例。
4. 正常走盤（Push）。
5. 半輸。
6. 其他比例的部分輸，保存確切比例。
7. 全輸。
8. 取消退本（Void）。
9. 待結算。
10. 無法結算，附原因及處理狀態。

此表同時含結算結果及未完成狀態，不把待結算／無法結算當已發生的比分結果類別。契約賽果類型與含退水成本後的淨收益正負分別保存。Void 與 Push 分開；Void 仍保留於原始母體、接受紀錄及覆蓋統計，不得從所有分母刪除。依期間與契約處理部分有效／部分取消。

### 6.3 輔助診斷的解讀邊界

- **Filter ablation：** 移除關卡後，重跑主方向選擇及整個策略；只報指定基準下的 OOS 策略差異。事後增益不是已識別因果貢獻，也不等於當時確有正 EV 機會。
- **Latency：** 保存評估後預定延遲的價格，作延遲敏感度；一分鐘後優勢消失不能證明原報價買不到。實際可取得性以當時接受／報價證據判定。
- **CLV：** 同市場、規則與時間口徑下作收盤參考；須定義去水及變盤比較方法，不能一概當低變異證據、真實機率或盈利證明。
- **相關結構：** 同場多方向／多版本不算獨立證據，不同場或不同時段也不當然獨立。分群／block bootstrap 方法、叢集數、跨日相關與少叢集限制須交代並作敏感度分析。
- **收益診斷：** 除 ROI 與區間外，檢查最大回撤、收益集中度、期間／聯盟／球隊／市場及機率區間，避免由少數場次代表整體。

- 舊資格歷史仍可讀及留存；延遲回報的真實接受結果照實記錄，不能以目前已過期抹除。正式接受／委託能力若系統並無提供，標實際範圍而非假裝已有外部交易整合。
- 失效事件及目前指標不得覆寫舊分析完成版本。重新核准須新證據與版本。

### 附錄 B：同場主方向排序【待核對、待完成】

- 固定第一至第 N 排序欄位、定義、單位與優先序，不預設未核對的 W／R／S 組合公式。
- 決定小數精度、同分及相近容許範圍、固定 tie-break、空值／無報價排除、規則版本 `ranking_rule_version`。
- 只在當時合格集合中選；無合格者不產生可下注主方向。其餘方向及未達標原因保存。
- 調整排序視為策略修改，需相應時序驗證；不能賽後挑贏。

### 附錄 C：母體、快照、事件與統計分母【待核對、待完成】

- 定義原始賽事收錄條件、時間範圍、賽事身分、方向與版本去重鍵，包含未開始、處理中、無盤、失敗、資料不足及 BLOCKED。
- 逐指標固定分子／分母、結算狀態集合、Void／Push／未結算／無法結算處理及本金加權。
- 三類評估快照分清：
  1. **固定截止時點模型比較：** 預先指定截止，選當時可用分析，定義新鮮度與缺失處理。
  2. **首次合格觸發策略模擬：** 事前定義首次觸發規則、當時可取得價格、後續失效與是否模擬接受。
  3. **實際接受績效：** 實際接受之方向、價格、本金、事件時間、回報時間及契約，不以觸發代替接受。
- 首次候選、發出委託、實際接受是另一套業務事件分類，與上述三類快照不假設一一對應。皆須可獨立辨識、關聯及追溯；同一追加事件表或分表均可，不互相冒充／覆寫。
- 「開賽前最後有效分析」是一項可另定義的策略，不等於固定如 T−30 分鐘模型比較；不能把兩者混稱。
- 保存完整方向／版本與結果，同時指定每種報表的合法去重，不把多方向／多次分析當獨立比賽。

### 附錄 D：模型機率、跨期與人員一致性【待核對、待完成】

- 定義非負、各分布加總一的浮點容許誤差、比分網格、尾端質量、網格外觀測與對數損失規則；不能丟掉尾端再假稱原分布。
- 機率加總只在比分分布與各自互斥完備市場結果內檢查，不對跨市場八方向強制正規化。非 50% 結算依真實契約映射。
- 跨期先檢查逐隊及總進球門檻單調性，但若宣稱完整一致，須有合法時間路徑或存在保持兩隊進球不倒退的 HT/FT 聯合配置。可用適當可行性檢查，不強制昂貴模擬；須說明截斷／尾端處理與實際保證層級。
- 必要反例：HT `(0,2)`／`(2,1)` 各 0.5；FT `(1,1)`／`(2,2)` 各 0.5。逐隊及總進球邊際單調仍無合法不倒退聯合配置，因兩個 HT 狀態均不能到 FT `(1,1)`。不得以一維檢查通過代替完整二維保證。
- 陣容、替補、換人、預期分鐘及實際時間口徑須按目標賽事規則，包含補時、紅牌減員等情境。球員分鐘與全隊分鐘守恆按相同口徑計算；不得任意固定忽略特殊情境。
- 註明歷史強度與當場人員調整的基準陣容及責任，防止同一缺陣、角色、疲勞或分鐘效果重複加減。

### 附錄 E：既有 QA 與端到端驗收【待核對、待完成】

- 列出既有警示與阻擋的代碼、公式、閾值、單位、原因及分析狀態映射，先查驗再保留，不因本文件調整其他運動口徑。
- 端到端核對：原始外部盤口／資料 → 解析 → 儲存版本 → 分析輸入／輸出 → API 與畫面／紀錄 → 最終契約損益。數值可按明定顯示精度轉換，但身分、方向、期間、契約及版本語意須一致且可回算。
- 契約測試涵蓋各格式、方向、期間、整數／quarter／比例邊界、退水／費用、異常狀態與結果更正；抽樣相符不是完整契約測試。
- 驗證不可變性、截止時間查詢、未知歷史不追認、候選過期後授權拒絕、價格重核及舊任務晚完成不發布等完整流程。
- 明列可重現的測試案例、預期結果、實際結果、執行版本與環境。合成案例只能證明程式行為，不能作模型準度／盈利證據。
- 本地／測試通過與 Production 驗收分開。正式驗收須對同一部署版本核對真實資料流、狀態、契約與證據；不得只以畫面綠燈宣稱完成。

## 9. 推進順序與完成判定

1. 完成四模組前置事實核對，逐項標記證據與 UNKNOWN。
2. 填妥 A–E 的可執行規則、既有系統映射、契約及驗收基準。
3. 依已確認需求實作，完成適用的單元／契約／並行／端到端測試。
4. 於對應部署完成正式環境驗收，另外以未參與開發選擇的資料驗證模型與低頻策略。

規格可先保存；尚未確認事項持續明確標示。工程功能完成、歷史可回放、模型概率可靠及實際正收益是不同結論，須各自有證據。允許零場是可執行的篩選要求，不是準度或收益保證。
